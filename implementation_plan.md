# Comprehensive Implementation Plan

This document outlines the end-to-end implementation details for your multi-phase request, spanning the frontend, backend, machine learning engine, and database.

## User Review Required
> [!IMPORTANT]
> **API Keys**: Implementing the Gemini API (Phase 4) requires a valid `GEMINI_API_KEY`. Please ensure this is available in your backend `.env` variables or Render Dashboard. No YouTube API key is required as we will use a server-side scraping package (`youtube-search-python`).
>
> **Database**: We will add a new collection `EduXcelLogin` in MongoDB to track daily logins and streaks.

## Proposed Changes

---

### Phase 1: Authentication, Onboarding & Data Sync

#### [NEW] `frontend/src/pages/Onboarding.tsx`
- Build a dedicated, role-based multi-step form for Students (metrics, study habits, platform preferences) and Teachers (department, subjects taught).
- Upon submission, update the MongoDB `User` document with `isOnboarded: true`.

#### [MODIFY] Frontend Routing & Protection
- Modify `App.tsx` and auth guards to forcefully route `!user.isOnboarded` users to the Onboarding screen immediately after login.
- Audit `StudentDashboard`, `FacultyDashboard`, and `AdminDashboard` to replace all dummy `href="#"` links with functional routes.

#### [MODIFY] Backend API Routes
- Build or update specific endpoints (`/api/students/me`, `/api/faculty/overview`, `/api/admin/system`) to serve live aggregated data rather than static JSON placeholders, syncing dashboards in real-time.

---

### Phase 2: Daily Mechanics & ML Integration

#### [NEW] `backend/src/models/EduXcelLogin.ts`
- Create a Mongoose schema mapped to the `EduXcel` collection inside the `users` context to track `userId`, `loginDate`, and calculate consecutive `streak`.

#### [MODIFY] `backend/src/controllers/authController.ts`
- Inject a tracker routine on every successful login/callback to insert a record into `EduXcel` collection and compute the user's current streak.

#### [MODIFY] Frontend Greeting Cards
- Update the Dashboard headers to fetch the `streak` count from the backend and display an animated CSS fire emoji (🔥) that increments dynamically.

#### [MODIFY] `backend/src/services/mlService.ts`
- Route live database metrics (grades, attendance, study hours) instead of dummy data when calling the Python ML Engine `predict` route.

---

### Phase 3: Dynamic Recovery Path & YouTube Engine

#### [NEW] `ml-engine/youtube_module.py`
- Utilize the `youtube-search-python` library to dynamically search YouTube for topics based on the student's weak subjects/predictions. Extracts channel names, titles, and thumbnails.

#### [MODIFY] `ml-engine/main.py`
- Expose a new FastAPI endpoint `/recommend` that combines the ML risk prediction payload with live YouTube results.

#### [MODIFY] `frontend/src/pages/student/RecoveryHub.tsx`
- Replace static cards with a dynamic step-by-step academic roadmap generated by the ML engine.
- Integrate the video recommendations, styling one specific video as the "Top Pick" (AI Recommended Highlight) and rendering the remaining as standard selectable options.

---

### Phase 4: UI Polish & Gemini API Chatbot ("Xcello")

#### [MODIFY] Global Tailwind CSS / Theme
- Audit `frontend/src/index.css` and component classNames to repair Light/Dark mode contrast issues (specifically color inversions in backgrounds, text, and cards).

#### [MODIFY] `frontend/src/components/shared/XceloChatbot.tsx`
- Overhaul the floating chat button. Remove the standard circle icon and replace it with a waving robot GIF and a speech bubble reading: *"Hii I am Xcello"*.
- Connect the mock chat interface to a live backend endpoint.

#### [NEW] `backend/src/controllers/chatController.ts`
- Integrate `@google/genai` to communicate with the Gemini API.
- Inject role-specific system prompts:
  - **Student**: Acts as a personal tutor analyzing academic paths.
  - **Faculty**: Acts as a teaching assistant for cohort analytics.
  - **Admin**: Acts as a system administrator managing platform health.
